# 数据格式

所有中间产物都在 `work/` 下，路径由 `src.common.paths` 解析，不依赖当前目录。

## OCR 逐帧记录

`work/ocr/<key>.jsonl`，每行一帧：

```json
{"t": 12, "band": [[10, 10, 40, 200, "旅行者", 0.98]], "panel": [], "opt": [], "desc": []}
```

- `t`：秒（从视频起点算）。
- `band` / `panel` / `opt` / `desc`：OCR 框数组。
- 框格式：`[y1, x1, y2, x2, text, score]`。
- `band` 同时包含姓名带与底部字幕；`merge` 按位置与文本判断姓名/正文。

特殊采集：

- `work/bub/<key>.jsonl`：`{"t": 秒, "bub": [框...]}`，头像气泡区。
- `work/map/<key>.jsonl`：`{"t": 秒, "map": [框...]}`，右侧行动面板。
- `work/align/tips_<key>.json`：`{"秒": [框...]}`，地图浮窗整块。

## 逐段 txt

`work/txt/draft/<key>_<title>.txt`（build）与 `work/txt/final/<key>_<title>.txt`（align）：

```
【段落标题】
对应视频：视频文件名.mp4
时长：mm:ss
台词来源：画面内嵌中文字幕（OCR 识别）
说话人来源：画面中显示的角色名，逐帧识别后与台词按画面时间对齐
标记说明：??? = 游戏画面本身未显示姓名；画面文字 = 界面/教程/字卡/选项/任务目标等非台词文本
========================================================

[00:01] 旅行者：你好，世界。
[00:03] 画面文字：任务目标·前往某处
```

- `====` 之前是头部，之后是正文。
- 可选头部行：`任务描述：...`。
- 正文只允许两种行：
  - `[mm:ss] 说话人：正文`
  - `[mm:ss] 画面文字：...`
- 说话人未知时用 `???`；`???` 只表示画面没显示姓名，不表示 OCR 失败。

## 对齐报告

`work/align/<key>.json`：

```json
{
  "key": "01_intro",
  "title": "段落标题",
  "fixes": [{"t": 12, "ocr": "...", "wiki": "...", "sp": "说话人", "sim": 0.93}],
  "review": [{"t": 20, "ocr": "...", "wiki": "...", "sp": "...", "sim": 0.75}],
  "unmatched": [{"t": 30, "body": "...", "best": 0.4, "cand": "..."}]
}
```

- `fixes`：自动替换，可直接采用。
- `review`：相似度中等，需人工看抽帧。
- `unmatched`：未匹配到剧本，保留 OCR 结果。

## 交付 Markdown

`assemble` 输出到 `config/assemble.json` 指定的文件（默认 `transcript.md`）：

```
# 标题

> 依据 N 段剧情视频的画面字幕与界面文字整理，未使用语音识别

## 编辑说明
...

## 目录
- **幕名**
  - 01　段落标题　（mm:ss）

## 幕名

### 01 段落标题

**任务描述**：...

> 对应视频：视频文件名.mp4　时长 mm:ss

[00:01] **旅行者**：你好，世界。
[00:03] **【画面文字】**任务目标·前往某处

---
```

- 台词：`[mm:ss] **说话人**：正文`。
- 画面文字：`[mm:ss] **【画面文字】**...`。
- 补录篇的段落标题前缀 `补录：`。

## 运行报告

`work/reports/<command>.json`：

```json
{
  "step": "doctor",
  "ok": true,
  "time": "2026-11-10T12:00:00",
  "checks": [{"name": "ffmpeg", "ok": true, "detail": "ffmpeg"}]
}
```

`ok` 与进程退出码一致，agent 以此判断步骤是否完成。
