# 踩坑经验

本文件保存实践验证过的经验，尤其是错字表与说话人变体。**不要以“精简”为由删除。**

## 下载与视频

- B 站分P用 yutto 下载；视频目录只读，不移动、不改名、不删除。
- 定位视频按文件名匹配，不依赖合集目录名。
- 分P清单以 B 站 API 为准，不以本地 dir 顺序为准。

## 抽帧与裁切

- `band` 默认 `1360×230 @ (280,780)`，同时覆盖姓名带与底部字幕。
- `full` 用于右侧战报、地图标签、菜单残片；其他分辨率改 `pipeline.json` 的 `crop` / `full_size`。
- 抽帧覆盖目标时间前后 1–2 秒，避免转场空帧。
- `decode failed: got 0 bytes` 基本是秒数超过视频长度。
- 大规模抽帧很占磁盘；`run` 跑完会删 `work/raw/<key>`。

## OCR

- `rapidocr_onnxruntime` 1.2.3：给 `RapidOCR()` 传任何 `det_*` / `rec_*` 参数时，必须显式补
  `det_model_path=None, rec_model_path=None`，否则 `KeyError: 'model_path'`。
- `OCR_THREADS`、`OCR_SCALE` 可覆盖并发与缩放；默认取 `pipeline.json` 的 `ocr`。
- 单字名牌会被 OCR 整个漏掉（如「琴」）：用 `profiles/corrections.d/<key>.json` 的 `name` 字段补说话人。
- 不要用字号高度区分姓名/标题：姓名行高 15–63px、教学卡标题 18–25px，区间重叠，按高度会误杀正常说话人；标题走白名单排除。
- 称号行括号会被 OCR 换成 `］`/`】`/`』`：`is_title` 先 `fix_brackets` 再判断；超过 8 字的机体/装备称号用 `is_plate`。
- 两行名牌（姓名 + 称号）且正文「……」未识别：`parse_band` 返回 name-only + heading；`merge` 的待定台词要能跨过插入的标题 screen。
- 教学卡标题会混进说话人白名单：跨段统计会把「圣土化的影响」带进 wl；`build_whitelist` 需排除 `CARD_TITLES`，新增说话人走 `profiles/names_extra.json`。

## 合并与说话人

- 姓名 + 职位被 OCR 并进正文时拆回说话人，例如「艾蒂安梅洛彼得堡看守朱斯蒂娜小姐……」。
- 名牌被并进正文（如「石头：石头「解翠行」老板…」），去掉正文开头的重复名字。
- 同一说话人 4 秒内被逐帧累积的截断/重识别台词，只保留完整的一条。
- 字幕帧丢失名牌时，同一句会以无姓名的画面文字再出现一次；按正文去重，去掉回声。
- 自由探索段玩家访问顺序与剧本不同，退化为全剧本无序匹配。

## 标点与括号

- `]`、`】`、`］` 统一成 `」`；`[`、`【`、`［` 统一成 `「`。
- 句中孤立的后引号要删；句尾未闭合的前引号要补，**补全必须覆盖「画面文字」分支**。
- 孤立后引号判断不能只看前一个字是不是汉字，`…」你还没忘掉…` 这种前一个字符是标点的情况也要算。
- **改完规则必须扫最终 Markdown**，只查逐段 txt 会漏。

## 形近字与固定替换

- 只做字典级确定项：`邪崇→邪祟`、`开拨→开拔`、`西风成垒→西风戍垒`、`孩人→骇人`、
  `小靓→小觑`、`弘导→引导`、`获花州→荻花洲`、`终干→终于`、`卵师傅→卯师傅`。
- 这些规则落在 `config/game_profile.json` 的 `typo_fix`，不要写死在代码里。
- 上下文相关乱码不能盲替（地名/界面文字插进句子中间），必须抽帧确认。
- 说话人变体不能只靠“同 key 取最高频”：`伊湿芙/伊涅芙`、`茜特拉莉/茜特菈莉`、
  `神里人/神里终人`、`格干里/格千里/柊千里` 的 key 本来就不同，必须显式映射（`name_fix`）。
- 界面残片按段精确过滤（`0000`、`4680感电v.90`、`975` 等），不要模糊包含；过短的画面文字必须人工判定。

## 面板与浮层

- `desc` 浮层用「｜」拼标题与正文，不是「姓名 + 正文」；`emit_screen` 的姓名拆分只用于 band 文本。
- 「画面文字」的引号补全会因下一行也是画面文字而被跳过；画面文字分支必须无条件补。
- 世界名牌噪声（浮动姓名、距离）按“宁多录”保留为画面文字，但保持为 screen，不能拆成台词。
- `tips` 浮窗 / 行动面板整块重采，`desc` 裁切只截到一角。

## 工程与重跑

- Windows 下 `open(..., "w")` 默认写 CRLF；仓库统一 LF，写 txt/md 时显式 `newline="\n"`。
- 路径统一用 `src.common.paths` 的 `ROOT`/`WORK`，不要相对当前目录。
- 配置只改实际副本；实际 `config/*.json` 不入库，只提交 `.example`。
- 已交付段按只读快照处理；重跑前先做影子 diff，比较新增/删除行。
- 门禁只扫逐段 txt 不够：引号平衡、抬头、差集都要在最终 Markdown 上复核。
- 完成判定不要只凭文件字节数；OCR jsonl 要检查行数与末尾完整性。

## 人工修正与过滤

- `profiles/corrections.d/<key>.json`：分段人工修正；`profiles/corrections.json` 为全局修正。
- `profiles/screen_drop.json` / `speaker_drop.json` / `name_unknown.json`：按段配置的画面文字/姓名过滤与未知名单。
- 改清洗规则后按序重跑：`align` → `work/txt/final` → `assemble` → 最终 Markdown。

## 协作与子 agent

- **判断密集的校对自己做**；机械且可自校验的任务写脚本；子 agent 只适合“独立复核/发现问题”。
- 真要派：按产物派、给机械化终止条件、给验证动作设上限、强制周期性落盘、派活期间冻结共享脚本。
- 一张抽帧图是上下文里最贵的东西；读几十张图后任务理解会被压到后面，所以落盘频率比“再看一帧”重要。

## 交付格式

- 时间 `[mm:ss]`；画面文字用 `**【画面文字】**`；台词用 `**说话人**：正文`。
- `???` 只表示游戏画面本身没显示姓名，不表示 OCR 失败。
- 编辑说明写清有剧本页/无剧本页的来源差异。
- 只关闭自己启动的进程，不要用 `taskkill /F /IM node.exe` 或 `msedge.exe` 一刀切。
